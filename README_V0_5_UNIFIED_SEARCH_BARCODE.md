# CarbCalc UA MVP 0.5 — Unified Food Search + Barcode

Checkpoint: об’єднаний текстовий та barcode-пошук.

## Що реалізовано
- Вільний текст із кількістю: `150 г вареної гречки на воді`, `2 шт печива Марія`.
- Український нечіткий пошук із контекстним ранжуванням стану/приготування.
- Штрихкод через камеру (`mobile_scanner`).
- Єдиний `FoodSearchService`: текст і barcode приводять до одного Product-потоку.
- Пошук спочатку перевіряє локальні дані, потім Open Food Facts.
- Користувацькі продукти з локальної SQLite-бази також беруть участь у текстовому пошуку.
- Дані Open Food Facts показуються для перевірки; автоматичне збереження не виконується.
- Після підтвердження зовнішній продукт зберігається локально та стає доступним офлайн.
- Збережено одиниці `г / мл / шт / порція`.
- Для локальних продуктів зберігаються параметри `г/шт`, `г/мл`, `г/порція`.
- SQLite піднято до version 5 з міграцією.

## Користувацький потік
`Ввести текст` → `варіанти` → `підтвердити продукт` → `кількість/одиниця` → `вуглеводи + ХО` → `щоденник`.

або

`Сканувати` → `EAN/UPC` → `локальна база / Open Food Facts` → `перевірити` → `кількість/одиниця` → `вуглеводи + ХО` → `щоденник`.

## Принцип безпеки
Штрихкод не означає автоматичної достовірності харчових даних. Дані зовнішнього джерела вимагають підтвердження користувачем. CarbCalc UA не визначає дозу інсуліну.

## Наступний етап
Покращити екран підтвердження barcode-продукту, додати редагування отриманих харчових даних та повноцінне збереження користувацького продукту з усіма одиницями/порціями.
